# x3wcx — каталоги X3 и файлы .pck в Total Commander

[![build](https://github.com/DIMOSUS/x3wcx/actions/workflows/build.yml/badge.svg)](https://github.com/DIMOSUS/x3wcx/actions/workflows/build.yml)

[English](README.md)

Плагин-упаковщик (WCX) для Total Commander. Открывает как обычные архивы:

- **каталоги X3** (X2, X3: Reunion, Terran Conflict, Albion Prelude): `NN.cat` с индексом и парный `NN.dat` с данными;
- **файлы `.pck`** (сжатые gzip XML и TXT): архив с одним файлом внутри.

Файлы можно смотреть (F3), распаковывать (F5), править (F4), добавлять, заменять и удалять прямо в TC. Внешние
библиотеки не нужны: deflate/inflate встроены (`src/flate.cpp`).

**Скачать:** `x3wcx.zip` на странице [Releases](https://github.com/DIMOSUS/x3wcx/releases) (обе сборки и
`pluginst.inf`).

## Установка

1. Скопируйте `x3wcx.wcx` (32-битный TC) и `x3wcx.wcx64` (64-битный TC) в одну папку, например
   `%COMMANDER_PATH%\Plugins\wcx\x3wcx\`. Проще открыть в TC архив `x3wcx.zip`: TC сам предложит установить плагин
   (файл `pluginst.inf`) и привяжет его к `cat`.
2. **Конфигурация → Настройка → Плагины → Плагины архиваторов (WCX) → Настройка**:
   - в поле расширения введите `cat`, нажмите «Новый тип» и выберите `x3wcx.wcx` (64-битный TC сам возьмёт `.wcx64`
     рядом);
   - повторите для `pck`.
3. Если расширение уже занято другим плагином, TC спросит, какой использовать; `.dat` привязывать не нужно.

Архив с другим расширением можно открыть по Ctrl+PgDn: плагин узнаёт каталог по первой строке индекса
(`*.dat` после расшифровки), а `.pck` по сигнатуре gzip, с маской или без. По содержимому `.pck` узнаётся, только если
в заголовке gzip нет имени файла, как у игры: обычные `.gz` от gzip плагин не перехватывает.

## Что умеет

| | `.cat` + `.dat` | `.pck` |
|---|---|---|
| Список, F3, F5, проверка | да | да, один файл |
| Новый архив (Alt+F5) | да, `NN.cat` + `NN.dat` | да, без маски, как у игры в `addon\scripts` |
| Добавление | дописывается в конец `.dat` на месте, `.dat` не переписывается | — |
| Замена (тот же путь, регистр не важен) | файл остаётся на своём месте в индексе, со своим именем | только файл с тем же именем (регистр и расширение не важны), чужой отклоняется (`E_NOT_SUPPORTED`); маска и ключ сохраняются |
| Удаление, в том числе папок | да | нет (`E_NOT_SUPPORTED`) |
| F4 — правка файла в архиве | да | да |

- **Пути внутри каталога** пишутся с прямыми слэшами и в latin1, как у игры; имя с символами вне latin1 плагин
  отклонит (`E_BAD_DATA`).
- **Первая строка индекса** (имя `.dat`, игрой не используется) при изменении сохраняется как была. В новом каталоге
  в ней записано имя парного `.dat`. Новый каталог совпадает байт в байт с тем, что пишет `x3kc cat --pack`.
- **Расширение файла внутри `.pck`** определяется по папке: `scripts`, `t`, `director`, `maps` → `.xml`, `types` →
  `.txt`. В остальных папках — по содержимому: `.xml`, если текст начинается с `<`, иначе `.txt`. Это важно для `.pck`,
  открытого изнутри каталога: TC распаковывает его во временную папку, и имя исходной папки теряется.
- **Прогресс и отмена** работают при распаковке и записи. При отмене каталог остаётся прежним.
- **Поиск текста** (Alt+F7, «искать в архивах») заглядывает внутрь каталогов и `.pck`.
- **`.pck` из нескольких gzip-членов подряд** читается целиком, как в `unpck.py`, и при записи сохраняется одним членом.

## Надёжность записи

- **Добавление** дописывает данные в конец `.dat`, затем атомарно заменяет `.cat` (через временный файл
  `*.x3wcx-tmp` и переименование). Если что-то не вышло, `.dat` обрезается до прежней длины. Старый индекс не
  ссылается на хвост `.dat`, поэтому каталог цел при сбое на любом шаге.
- **Удаление последних файлов** сначала пишет новый индекс, потом обрезает `.dat`.
- **Замена и удаление из середины** пишут новые `.dat` и `.cat` рядом (`*.x3wcx-tmp`), затем подменяют пару
  переименованиями. Старая пара на это время сохраняется как `*.x3wcx-bak` и удаляется после успеха; при ошибке она
  возвращается на место. Если Windows упадёт ровно между двумя переименованиями, верните оба файла из `*.x3wcx-bak`
  вручную. Пока рядом с каталогом лежит `*.x3wcx-bak`, плагин отказывается его менять (`E_ECREATE`), чтобы не
  затереть, возможно, единственную целую копию: восстановите пару или удалите лишние файлы.
- **Место на диске.** Для такой перезаписи нужно свободное место размером с `.dat`. Для стоковых `01.dat` (1,3 ГБ) и
  `02.dat` (2,1 ГБ) это и долго, и требует места.
- **Каталог без `.dat`.** Если `.dat` пропал, а в индексе есть файлы, добавление отклоняется, пустой `.dat` не
  создаётся.
- **`.pck`** пишется через временный файл и переименование.

## Внимание: правка стоковых каталогов меняет игру

Каталоги `01.cat`–`13.cat` и `addon\01.cat`–`addon\04.cat` — данные самой игры. Любое изменение в них сразу меняет
игру, может испортить совместимость с сохранениями и пропадёт при проверке файлов Steam. **Моды кладите в новый
каталог со следующим номером**: игра читает каталоги по порядку, и файл из каталога с бо́льшим номером перекрывает
одноимённый из меньшего (так устроен, например, `addon\05.cat`). Новый каталог создаётся в TC так: выделите файлы,
нажмите Alt+F5 и задайте имя `addon\06.cat`, выбрав упаковщик `cat`.

Перед любыми экспериментами со стоковыми каталогами сделайте копию.

## Вложенные архивы: `.pck` внутри `.cat`

TC умеет входить в архив внутри архива: Enter на `.pck` в каталоге распаковывает его во временную папку и открывает
плагином. По справке TC (раздел «Packed files»), при выходе из вложенного архива эта временная копия удаляется. Ни в
справке, ни в истории версий TC 11.56 не сказано, что изменения вложенного архива упаковываются обратно во внешний. Это
нужно проверить руками (см. ниже). **Пока считайте, что правки внутри вложенного `.pck` во внешний `.cat` не
возвращаются.** Надёжный путь такой:

1. скопируйте `.pck` из каталога на диск (F5);
2. откройте его там и правьте как архив (F4 на `.xml` внутри);
3. скопируйте исправленный `.pck` обратно в каталог (F5 в панель с открытым `.cat`) — он заменит старый на том же месте.

## Ограничения

- Время файлов в каталоге не хранится: все файлы показываются с датой `.cat`.
- Пустые папки в каталоге не хранятся: папки берутся только из путей файлов.
- Распаковка `.pck` целиком в памяти (файлы игры — до нескольких МБ).
- Фоновая работа TC (`GetBackgroundFlags`) не объявлена: TC выполняет операции в основном потоке.
- `.pbd`/`.pbb` (сжатые модели) показываются как обычные файлы и не распаковываются.

## Сборка и тесты

Нужна Visual Studio 2019+ (или Build Tools) с компонентом C++:

```
build.cmd
```

Результат: `build\x3wcx.wcx`, `build\x3wcx.wcx64`, `build\x3wcx.zip` и тестовые драйверы
`build\wcxdrv32.exe`/`wcxdrv64.exe`. Драйвер загружает плагин и вызывает экспорт так же, как TC.

Тесты сравнивают плагин с эталоном на Python — `catx.py` и `unpck.py` из [x3kc](https://github.com/DIMOSUS/x3kc):

```
git clone https://github.com/DIMOSUS/x3kc ..\x3kc
python tests\test_wcx.py --x3kc ..\x3kc                                  # синтетические каталоги, несколько секунд
python tests\test_wcx.py --x3kc ..\x3kc --game "C:\Games\X3 Terran Conflict" [--quick]   # настоящие
```

- Без `--game` тесты собирают маленькие синтетические каталоги и `.pck`, устроенные как у игры; это же
  запускает CI. С `--game` берётся папка игры (её и x3kc можно задать переменными `X3_GAME` и `X3KC`).
- Каталоги игры только читаются: проверяется список и содержимое всех файлов во всех каталогах.
- Изменения делаются на копиях во временной папке и сравниваются побайтно с `catx.write_catalog`.
- `.pck` проходят круг распаковка → упаковка → распаковка; результат проверяет и `gzip` из Python.
- `--quick` пропускает два больших каталога (01, 02).
